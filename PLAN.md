# План (зафиксирован до обучения моделей)

## Данные

Yambda-50M (Яндекс Музыка): 47,8 млн событий, 10 000 пользователей, 934 057 треков, 1 505 дней.
События: прослушивание (с долей прослушанного), лайк, дизлайк, отмены; флаг `is_organic`
(1 — пользователь нашёл трек сам, 0 — трек пришёл из рекомендаций: персональная лента, плейлисты).

Наблюдения до плана: 71 % прослушиваний — повторы уже знакомых треков; медиана доли прослушанного 100 %,
но четверть прослушиваний обрывается на первых 7 %; ~2 000 активных пользователей в день; половина
прослушиваний — из рекомендаций.

## Что считаем положительным откликом

**listen+** — прослушано больше 50 % трека (определение авторов датасета), или **лайк**.
Пропуск (≤ 10 %) и дизлайк — отрицательные сигналы для признаков, но не цели.

## Разбиение по времени (без утечки будущего)

| Часть | Дни | Зачем |
|---|---|---|
| история | 0 … 1 490 | обучение моделей кандидатов и признаков |
| валидация | 1 491 … 1 497 | метки для обучения ранкера, подбор гиперпараметров |
| тест | 1 498 … 1 504 | финальная оценка, открывается один раз |

Для теста модели кандидатов и признаки пересчитываются на истории + валидации (окно сдвигается на неделю).
Оцениваются пользователи, у которых в тестовой неделе есть хотя бы один положительный отклик
(холодных пользователей в датасете нет).

## Две задачи

1. **Прослушает** — любые треки с откликом в тестовой неделе, включая повторы.
2. **Откроет** — только треки, с которыми у пользователя не было ни одного события до начала теста.
   Это продуктовая задача рекомендаций; в первой задаче выигрывает «повтори любимое».

## Метрики

- Ранжирование: **NDCG@10** (главная), Recall@10, Recall@100.
- Отбор кандидатов: Recall@200 — доля положительных, попавших в кандидаты (потолок для ранкера).
- Шире точности: покрытие каталога (доля уникальных треков в выдачах), новизна (средний −log популярности),
  доля выдачи из «головы» (топ-1 % треков).
- Для разниц моделей — 95 % ДИ бутстрепом по пользователям (парный: одни и те же пользователи).

## Модели (по порядку сложности)

1. Популярное за последние 30 дней; популярное за всё время.
2. «Ещё раз своё» — самые слушаемые пользователем треки (только задача 1).
3. Исполнители пользователя — популярные треки его любимых исполнителей (без уже знакомых — для задачи 2).
4. Item2item по совместным прослушиваниям за короткое время.
5. ALS (implicit) на взвешенных откликах с затуханием по времени.
6. Двухэтапная схема: кандидаты из 1–5 → LightGBM LambdaRank на признаках пользователя, трека и пары.

## Смещение обратной связи

Половина откликов — на треки, которые показала прошлая рекомендательная система. Метрики считаются отдельно
для откликов `is_organic = 1` и `0`: модель, которая лишь воспроизводит старые рекомендации, выиграет на `0`
и проиграет на `1`.

## Решение

Какую модель нести в A/B-тест: лучшая по NDCG@10 в задаче «откроет», если разница с более простой значима
(ДИ не накрывает 0) и покрытие каталога не хуже популярного более чем вдвое. Плюс что мерить в A/B
и какие защитные метрики добавить.
